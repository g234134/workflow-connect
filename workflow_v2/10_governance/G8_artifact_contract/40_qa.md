## 1. 轨定位

**ART-QA-*** 定义 **checker-reviewer**（及等价 QA 角色）在验收收口时必须产出的**只读验收物**。QA 轨**消费** Eng 轨 `ART-ENG-*`，并产出可 append 的 battle report 内层草稿；**禁止**将 checker 外层 JSON 整包当作 Progress 战报。

## 4. 分 Artifact 契约

### 4.1 ART-QA-REV — Checker Review Verdict

**目的**：独立验收结论；父 agent／尚書省据此决定是否进入封存。

| 字段 | 必填 | 说明 |
|------|:----:|------|
| `ok` | ✓ | 流程是否成功产出验收包 |
| `ticket_id` | ✓ | 与任务卡一致 |
| `accepted` | ✓ | 是否接受交付（布尔） |
| `verdict` | ✓ | `accepted` \| `accepted_with_gaps` \| `rejected` \| `blocked` |
| `evidence` | ✓ | 见 §4.3 |
| `scope_check` | ✓ | `within_ticket` + 可选 `extra_files` |
| `dod_checklist` | ✓ | 见 §4.2 |
| `gaps` | ✓ | 无则 `[]` |
| `risks` | ✓ | 无则 `[]` |
| `follow_up_tickets` | — | 建议另开票项 |
| `tooling_checks` | — | 见 §5；W2-2 NBT-T01～T07 勾选摘要（**推荐**，非 blocker 必填） |
| `battle_report_json_draft` | ✓* | 见 §4.5；*append 前必填 |
| `message` | ✓ | 给尚書省／父 agent 的收口句 |

| 类别 | 规则 |
|------|------|
| **blocker** | `accepted: true` 但任一条 `evidence.exit_ok` 为 false；`scope_check.within_ticket: false`；`verdict` 与 `accepted` 矛盾 |
| **IMP 门槛** | **`IMP-ARCHIVE-PENDING` 入口前**必须就绪（`rejected`／`blocked` 则不得进入 archive_pending 标 done） |
| **确认方** | **checker-reviewer** 产出；**尚書省** 对 `accepted_with_gaps`／override 裁裁决 |

**verdict 与 IMP 关系（v0.1）**

| verdict | 可进入 IMP-ARCHIVE-PENDING | 说明 |
|---------|:--------------------------:|------|
| `accepted` | ✓ | 全证据通过 |
| `accepted_with_gaps` | ✓ | gaps 已列；不得隐瞒 skeleton／placeholder |
| `rejected` | ✗ | 退回 `IMP-ACTIVE` |
| `blocked` | ✗ | 验证不可跑；写 Progress 阻塞 |

### 4.2 ART-QA-DOD — DoD Checklist

**目的**：四流派最低覆盖的 QA 镜像是 Eng 轨 `ART-ENG-DOD` 的 checker 侧复验。

| 键 | 含义 | Eng 对应 |
|----|------|----------|
| `context_source` | Context／Source 已追溯 | ART-ENG-CTX |
| `incremental_honest` | skeleton／placeholder 诚实分栏 | ART-ENG-WR §2–§3 |
| `debugging_evidence` | 有 runner 证据或标 blocked | ART-ENG-EVD |
| `no_forbidden_zone` | 未越禁或未留痕 | ART-ENG-WR §7 |

| 类别 | 规则 |
|------|------|
| **blocker** | 任一键为 `false` 时 **`accepted` 不得为 true** |
| **IMP 门槛** | 随 `ART-QA-REV`；**`IMP-ARCHIVE-PENDING` 前** |
| **确认方** | **checker-reviewer** |

---

### 4.3 ART-QA-EVD — 验收证据包

**目的**：「先证据后结论」；每条 `acceptance_commands` 或任务卡指定 runner 须有一条 evidence。

| 子字段 | 必填 | 说明 |
|--------|:----:|------|
| `command` | ✓ | 实际执行命令 |
| `ran` | ✓ | 是否已执行 |
| `exit_ok` | ✓ | 退出码／断言是否通过 |
| `key_output` | ✓ | `ok` 字段或关键断言语义 |

| 类别 | 规则 |
|------|------|
| **blocker** | 任务卡列出的 `acceptance_commands` 未执行且未标 `blocked`；`exit_ok: false` 却 `accepted: true` |
| **IMP 门槛** | **`IMP-VERIFY` 出口前**（checker 完工时） |
| **确认方** | **checker-reviewer**（只读重跑）；必要时 **尚書省** 指定追加 runner |

**可选 CLI 证据**：若提供 battle report JSON 草稿，须跑 `python .\04_Workflows\_ops_cycle.py validate-report --json <draft>` 且 `ok: true`（缺必填栏则 blocker）。

---

### 4.4 ART-QA-SMOKE — Smoke 判定摘要

**触发**：任务卡或 Conditions 引用 `GOV_CORE_SMOKE_TEST_RUNBOOK_v0.1`／`RAG_SMOKE_TEST_RUNBOOK_v0.1` 或同类 smoke runbook。

| 字段 | 必填 | 说明 |
|------|:----:|------|
| `runbook_id` | ✓ | 如 `gov_core_smoke_v0.1` |
| `verdict` | ✓ | `pass` \| `partial` \| `fail` |
| `commands_executed` | ✓ | 与 runbook 对齐之命令清单 |
| `structured_summary` | ✓ | runbook §6 要求之关键 `ok` 字段摘要 |
| `runtime_metric` | ✓ | 须存在 `RUNTIME_METRIC`（runbook §6／§9） |
| `pass_fail_rationale` | ✓ | 一句判定依据 |

**Gov Core smoke（§6）最低 pass 语义**：Infra health 通过；ingest 有 chunk；ingest_verify 通过；master_status 写入证据；有结构化结果 + `RUNTIME_METRIC`。

**RAG smoke（§6）最低 pass 语义**：answer 模式 `ok: true` 且 `len(sources) >= 1`；若有 retrieve-only 则 `len(hits) >= 1`；有 `RUNTIME_METRIC`；未违禁区。

| 类别 | 规则 |
|------|------|
| **blocker** | `verdict: fail` 却 `accepted: true`；缺 `RUNTIME_METRIC`；未对照 runbook §6 却标 pass |
| **IMP 门槛** | smoke 门禁票：**`IMP-ARCHIVE-PENDING` 前** |
| **确认方** | **checker-reviewer** 对照 runbook §6；Eng 侧 `ART-ENG-EVD` 交叉验证 |

---

### 4.5 ART-QA-BR — Battle Report 内层草稿

**目的**：可 append 至 Progress 的**扁平** JSON；字段契约以 schema 为准，**本档不复制全文**。

**必填字段**（`ops_cycle_schema.json` → `battle_report.required_fields`）：

| 字段 | 映射建议（来自 Eng／QA） |
|------|-------------------------|
| `ticket_id` | 任务卡 |
| `role` | checker 或执行副官角色名 |
| `executed` | `ART-QA-EVD[].command` + Eng §1 摘要 |
| `results` | `verdict`、`accepted`、关键 `ok` 摘要、可选 `output_file` |
| `blockers` | Eng §5 或「无」 |
| `next_steps` | Eng §6 或 follow_up |

**可选字段**：`status`、`date_local`、`metrics`、`runbook_delta`、`standards_delta`、`forbidden_zone_note`、`override_note`（见 schema `optional_fields`）。

| 类别 | 规则 |
|------|------|
| **blocker** | 缺任一 `required_fields`；`status: done` 但 `blockers` 含未解决 P0；checker **外层** JSON 未抽出内层即 feed CLI |
| **IMP 门槛** | **`IMP-ARCHIVED` 入口前**（append 前须 `validate-report` pass） |
| **确认方** | **`_ops_cycle.py validate-report`** 机器验；**checker-reviewer** 内容验 |

**与 OPS_CYCLE 封存对齐**

| 模式 | 步骤 | QA 责任 |
|------|------|---------|
| minimal | `evidence` + `battle_report` | 备好 `ART-QA-BR` + 证据引用 |
| full | schema `archive_protocol.full_steps` 全链 | QA 验 battle report；milestone／forbidden_zone 等由副官按 `AGENTS.md` §封存协议执行，**非** QA 轨扩 scope |

## 5. Tooling-aware QA checklist（推荐）

> **制度源**：G10-2 **NBT-***（normative）；**实现层**步骤与字段 → `workflow_v2/20_pilot/W2-2_tooling_notes.md` §4–§4.1。  
> **性质**：**推荐**可选字段；**不**新增 ART-QA-REV 必填项；**不**替代 `dod_checklist` 四键或 `evidence[]`。

### 5.1 何时启用

| 情境 | checker 动作 |
|------|----------------|
| 任意 **ART-QA-REV** 收口 | 对照 W2-2 **NBT-T01～T05** 人工完成；建议写入 `tooling_checks` |
| `verdict: accepted_with_gaps` | 叠加 **NBT-T06**（`gaps_owner_and_release_judged`） |
| Release 轨／`IMP-RELEASE-DECISION` 前 | 叠加 **NBT-T07**（`release_dec_aligns_imp_state`） |
| 治理交叉引用类票（如 G8-RECON） | **T02** 须独立重跑 `wf_check_cross_ref.ps1` 或 §3 等价 grep |

### 5.2 可勾选清单（对应 NBT-T01～T07）

| Step | 检查意图 | G10-2 索引 | 推荐字段 | 未通过时的 verdict 倾向 |
|:----:|----------|------------|----------|-------------------------|
| **T01** | 不因 queue `DONE`／Eng `ok: true` alone 放行 | NBT-RT-01、NBT-AI-01 | `no_queue_or_eng_ok_only` | `rejected` |
| **T02** | 独立重跑 AC-1～AC-4（或票面 acceptance） | NBT-RT-03 | `re_ran_ac_grep` | `rejected` 或 `blocked`（命令不可跑） |
| **T03** | 亲自 Read diff 或变更清单 + spot-check | NBT-RT-04 | `read_diff_or_change_list` | `rejected`（scope 不可辩护） |
| **T04** | AC-5 语义审查（跳关／CHG 未变相改写） | NBT-AI-06 | `ac5_semantic_review` | `rejected` 或 `accepted_with_gaps`（仅文档 TODO） |
| **T05** | 票面 **ART-*** 在案卷可索引 | G8 各轨 §4 | `ticket_artifacts_indexed` | `rejected` 或 `blocked` |
| **T06** | `gaps[]` owner／`blocks_release` 已判 | NBT-GC-03 | `gaps_owner_and_release_judged` | 不得 `accepted`；维持 `accepted_with_gaps` 或 `rejected` |
| **T07** | **ART-REL-DEC** 与 `imp_state` 对齐 G7-3 | NBT-H-03 | `release_dec_aligns_imp_state` | Release **不得** approve；`rejected`／退回 QA |

**禁止（与 W2-2 §4 一致）**：仅脚本 PASS 即 `accepted`；仅读旧 QA JSON 的 `ok: true` 不再 grep；用 `_ops_cycle.py checklist` 代替本票 acceptance（NBT-RT-06）。

### 5.3 推荐 JSON 片段（ART-QA-REV）

在 §4.1 既有字段之外，可选增加：

| 字段 | 必填 | 说明 |
|------|:----:|------|
| `tooling_checks` | — | 对象；`checklist_id` 建议 `W2-2-NBT-T01-T07-v0.1` |
| `tooling_checks.<Txx键>` | — | 见 W2-2 §4.1 表；T06/T07 条件适用 |
| `tooling_checks.notes` | — | `N/A` 项说明 |

**与既有字段关系**

| 已有字段 | 关系 |
|----------|------|
| `evidence[]` | T02/T04 的 **证据本体**；`tooling_checks` 为勾选摘要 |
| `scope_check` | T03 为 true 时，`within_ticket` 应可辩护；二者不一致 → `rejected` |
| `dod_checklist` | 四流派键 **独立**；勿用 `tooling_checks` 顶替任一键 `true` |
| `gaps[]` | T06 为 true 时，每条 gap 宜含 `owner_ticket`／`blocks_release`（W2-1 样板） |

### 5.4 Verdict 裁決指引（推荐）

| `tooling_checks` 模式 | 建议 `verdict` |
|-----------------------|----------------|
| T01–T05 均为 `true`；无未关闭 blocker | `accepted` 或 `accepted_with_gaps`（仅低严重度 gap） |
| T02/T03/T05 任一为 `false` | **`rejected`**（或 `blocked` 若验证不可跑） |
| T04 `false` 但仅缺非阻塞文档 TODO | `accepted_with_gaps` + gap 列 owner |
| T06 适用但未判 owner／release | **不得** `accepted`；维持 `accepted_with_gaps` 直至补齐 |
| T07 适用且 `false` | Release 轨 **`rejected`**；QA 轨可仍为 `accepted*` 但 **不得** 前进 `IMP-RELEASED` |

checker **Completion criteria** 扩展（推荐勾选，写入 message 或 `tooling_checks`）：

- [ ] NBT-T01～T05 已执行且与 `evidence[]`／`scope_check` 一致  
- [ ] 若 `accepted_with_gaps`：NBT-T06 已判  
- [ ] 若 Release 收口：NBT-T07 已对照 **ART-REL-DEC**

## 6. QA 轨 Blocker 字段汇总

| Artifact | Blocker 字段／条件 |
|----------|-------------------|
| ART-QA-REV | `accepted: true` + 证据失败；scope 越界 |
