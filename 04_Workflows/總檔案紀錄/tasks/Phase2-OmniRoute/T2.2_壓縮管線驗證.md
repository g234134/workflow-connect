# T2.2 — 壓縮管線驗證（RTK / Caveman）

## 摘要

在 T2.1 chat 可用前提下，驗證 OmniRoute Context 壓縮（RTK、Caveman 等）是否生效並可在 Dashboard 觀測 token 節省。

## 根因分析

原 W3-008 無法確認「壓縮管線是否生效」，因 chat 端點當時未正確測試。T2.1 通過後，本任務驗證 **compression pipeline** 功能面，而非路由。

OmniRoute 宣稱 RTK + Caveman 可節省 15–95% tokens；需在 Dashboard Context 設定與 Logs/Costs 中交叉確認。

## 修復步驟

### 步驟 1 — 確認 Context 壓縮已啟用

1. 開啟 http://127.0.0.1:20128/dashboard/context  
2. 檢查 RTK、Caveman（或 LLMLingua 等）是否 **Enabled**  
3. 若未啟用，依需求開啟並 Save

### 步驟 2 — 準備長 context 測試 payload

```powershell
# 生成約 8KB 重複文字作為 user message
$long = ("The quick brown fox jumps over the lazy dog. " * 200)
$payload = @{
  model = "auto/best-coding"   # 或 T2.1 記錄的可用 model
  messages = @(
    @{ role = "user"; content = $long + "`n`nSummarize in one word." }
  )
  max_tokens = 20
  stream = $false
} | ConvertTo-Json -Depth 5 -Compress

$payload | Out-File "04_Workflows/總檔案紀錄/tasks/_artifacts\long_context_payload.json" -Encoding utf8
```

### 步驟 3 — 發送請求

```powershell
$body = Get-Content "04_Workflows/總檔案紀錄/tasks/_artifacts\long_context_payload.json" -Raw
$r = Invoke-WebRequest -Uri "http://127.0.0.1:20128/v1/chat/completions" -Method POST -Body $body -ContentType "application/json" -UseBasicParsing -TimeoutSec 120
Write-Host $r.StatusCode
$r.Content.Substring(0, [Math]::Min(500, $r.Content.Length))
```

### 步驟 4 — Dashboard 對照

1. **Logs** — 查看該請求是否有 compression / context 相關欄位  
2. **Costs** — 對比 input tokens 是否低於 raw prompt 估算（約 8KB ≈ 2000+ tokens 量級，壓縮後應明顯更低）

## 驗收測試

### T22a — 長 context 請求成功

**命令：** 步驟 3。

**通過標準：** HTTP 200，回應含有效 assistant content（非 error HTML）。

---

### T22b — Dashboard 可見請求紀錄

**命令：** 手動於 http://127.0.0.1:20128/dashboard/logs 搜尋剛才時間戳的請求。

**通過標準：** 能找到對應請求紀錄。

---

### T22c — 壓縮指標（定性）

**命令：** 於 Logs/Costs 查看 input tokens 或 compression 標記。

**通過標準（擇一）：**

- 有明確 compression 相關欄位／標籤，或  
- input tokens 明顯低於未壓縮估算（>30% 降幅即視為有效）

若 Dashboard 無法顯示細節，在「完成紀錄與後續建議」註明 **blocked-observability** 並保留 T22a 通過即可。

## 回滾方案與風險

在 Dashboard Context 關閉壓縮選項即可。
