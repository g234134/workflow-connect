> **位置**（repo 相對）：`04_Workflows/總檔案紀錄/tasks/`  
> （舊名「任務發布中心」；B′ 2026-07-12 已改名；B3 本檔由 `00_規則與使用說明.md` → `RULES.md`。）  
> **用途**：集中發布、追蹤、驗收 D 槽跨專案修復與測試任務  
> **建立**：2026-07-06（源自 D 槽總調度分析 Phase 1–3 任務計畫）

## 1. 設計原則

| 原則 | 說明 |
|------|------|
| **一任務一檔** | 每個可獨立執行／驗收的任務有專屬 `.md`，禁止把多個任務混在同一檔 |
| **總覽不代執** | `INDEX.md` 只做索引與進度看板，詳細步驟只在各任務檔 |
| **指令可複製** | 所有命令以完整 PowerShell／Python 區塊寫出，可直接貼上執行 |
| **關係可追蹤** | 每檔必含「相關任務」區塊，標明前置、後續、可並行 |
| **狀態可更新** | 每檔頂部 YAML 中繼資料含 `status`，完成後改為 `done` 並填 `completed_at` |
| **不修改原始碼目錄** | 本中心僅記錄任務；實際修復在各自專案路徑執行（除非任務明確授權） |

## 3. 任務檔案命名規則

| 元素 | 規則 | 範例 |
|------|------|------|
| Phase 資料夾 | `Phase{N}-{簡短主題}` | `Phase1-立即處理` |
| 任務檔名 | `T{Phase}.{序號}_{簡述}.md` | `T1.1_AI_HUB配置編碼修復.md` |
| 問題 ID | 對應總調度報告 ID（若有） | `W3-001`, `W1-001` |
| 新增任務 | 同 Phase 內序號遞增；跨 Phase 可重複序號 | `T2.3_…` |

---

## 4. 任務檔案必備區塊（固定順序）

每個任務 `.md` **必須**依序包含：

1. **YAML 中繼資料**（檔案最上方 `---` 區塊）
2. **摘要** — 一句話說明做什麼、為什麼
3. **背景與根因** — 複查結論、與原報告差異
4. **影響範圍** — 路徑、服務、是否阻斷生產
5. **相關任務** — 前置／後續／可並行（含連結路徑）
6. **修復步驟** — 編號步驟，含備份與回滾
7. **驗收測試** — 測試 ID（T{x}.{y}a…）、命令、通過標準
8. **完成紀錄** — 執行者、日期、備註（執行後填）

> 複製 `_templates/任務文件範本.md` 可確保格式一致。

## 5. YAML 中繼資料欄位

```yaml
---
task_id: T1.1                    # 唯一 ID
title: 任務標題
phase: 1                         # 1 | 2 | 3
priority: P0                     # P0=立即 | P1=近期 | P2=改善
status: pending                  # pending | in_progress | blocked | done | cancelled
issue_ids: [W3-001, W3-002]      # 對應總調度問題 ID
projects: [AI_HUB]               # 涉及專案
paths:                           # 主要路徑
  - D:\AI_HUB\config
depends_on: []                   # 前置 task_id 列表
blocks: [T3.3]                   # 被本任務阻擋的 task_id
parallel_with: [T1.2]            # 可同時進行
estimated_minutes: 15
assignee:                        # 執行者（可空）
created: 2026-07-06
updated: 2026-07-06
completed_at:                    # 完成時填 ISO 日期
---
```

---

## 6. 任務關係類型

| 類型 | 欄位 | 語意 |
|------|------|------|
| **depends_on** | 前置 | 必須先完成才能開始本任務 |
| **blocks** | 後續 | 本任務完成前，列出的任務不應標記 done |
| **parallel_with** | 並行 | 無依賴，可與列出任務同時執行 |
| **related** | 關聯 | 同一主題但無硬性順序（在「相關任務」段落補充） |

---

## 7. 狀態流轉

```
pending → in_progress → done
              ↓
           blocked（等待前置或外部條件）
              ↓
         cancelled（不再需要）
```

**更新規則：**

- 開始執行：改 `status: in_progress`，填 `assignee`
- 完成：改 `status: done`，填 `completed_at`，在「完成紀錄」寫驗收結果
- 若測試失敗：保持 `in_progress`，在「完成紀錄」寫失敗原因，必要時開子任務

---

## 8. 驗收測試命名

- 格式：`T{task_id 去掉點}{字母}` → 例：Task T1.1 的測試為 `T11a`, `T11b`
- 每個測試必含：**命令** + **期望結果** + **通過標準**（三者缺一不可）

## 9. 與其他紀錄目錄的關係

| 目錄 | 關係 |
|------|------|
| `04_Workflows/總檔案紀錄/_framework/` | 總調度主計畫（分析階段） |
| `04_Workflows/總檔案紀錄/_archive/Wave1-…` 等 | 問題發現來源（B′ 歸檔）；任務完成後可回寫「已解決」至原 W*_T*_問題報告 |
| 各專案原始碼 | 任務檔只記錄「在哪裡改」，不在此目錄存放 patch |

---

## 10. 新增任務流程（優化後）

1. 複製 `_templates/任務文件範本.md` 到對應 Phase 資料夾
2. 依命名規則重新命名
3. 填寫 YAML 與各區塊
4. 在 `INDEX.md` 新增一行並更新依賴圖
5. 若有 `depends_on`，在前置任務的 `blocks` 加入本 task_id
6. （可選）在來源 Wave 問題報告加連結：`→ 任務：../../tasks/Phase…/T….md`
